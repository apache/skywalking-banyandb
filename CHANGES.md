# Changes by Version

Release Notes.

## 0.12.0

### Features

- Add indexed measure QL LIKE and ILIKE filters with ESCAPE, using whole-value string indexes and bounded native wildcard execution.
- Compose scalar expressions inside and around measure QL aggregates, including computed aggregate inputs, HAVING and ordered results.
- Add bounded exact decimal SUM through DECIMAL_FROM_SCALED, with exact comparisons and fixed-scale string results.
- Add measure QL SELECT DISTINCT, computed and ordinal grouping, selectable time buckets, multi-key ordering with bounded top-k pagination, and exact count-distinct composition.
- Add typed measure QL expressions, masked CASE/COALESCE, raw field WHERE, grouped HAVING and compatible CONTAINS membership over shared columnar batches.
- Add SQL-correct measure QL grouping and multiple aggregates, with shared calls, weighted AVG, bounded local state and eligible native aggregate split/merge.
- Sample traces with source-stage native plugins before lifecycle migration, with durable decisions, checkpointed replay, and crash recovery.
- Add typed raw measure QL with WHERE time, aliases and bounded compiled-plan reuse, executed over shared columnar native batches.
- Add a native ICE v3 encoder that writes committed index generations compatible with existing readers.
- Cut the Property database's index writer over to the native segment plugin, selected by both the `property` and `schema-server` roles. `banyand/property/db.OpenDB` now acquires its exclusive `<Location>/lock` before scanning shard directories or opening any writer, and releases it if a later startup step fails. A rollback (flipping the selection back and restarting) reopens the same on-disk shards with the retained legacy writer unchanged.
- Complete the Property native role cutover for writes, immutable/NRT publication, repair, filtering, ordering, projection, and persistence. Native is the default for the `property` and `schema-server` roles; the legacy writer remains an explicit rollback path. Native ICE segments reserve `_id` as field ID zero and sort all other field names lexically for mixed-version merge compatibility. See the [Property native cutover verification](docs/design/archive/0.12.0/native-inverted-index/verification/property-native-cutover/README.md) report.
- Serve the Stream element index, the dump index resolver, and `bydbctl analyze` from the native index: exact, existence, range, NOT, MATCH (keyword, simple, standard, and URL analyzers), sort, snapshot, and external-segment receive.
- [Breaking Change] Property no longer indexes tags named `source`. Schema properties carry their full JSON spec in that tag; the value is still stored, returned, and sortable, but a Property query filtering on a tag named `source` no longer matches.
- Route native index file operations through `pkg/fs`, which gains page-cache advice (`AdvisePageCache`, `SetCached`) and error-returning `MkdirAll`, `ReadDirLimit`, `Lstat`, and `SyncDir`.
- [Breaking Change] Cut the per-segment series index (Measure, Stream, and Trace `seg-*/sidx`) over to the native index engine and remove the legacy index engine-backed series store: `pkg/index/inverted`'s series-only query builders, matchers, and tests are gone, and `banyand/internal/storage` no longer imports `pkg/index/inverted` or the retired third-party search engine at all. There is no engine flag and no switch between engines; upgrades are whole-cluster (stop every node, start the new binary on the same data directories) and rolling/mixed-version upgrades are not supported. Rollback is a file property, not a code path: `sidx` directories remain ICE v3 segments and snapshot v3 manifests the previous release already reads, and the new writer keeps writing `_id` doc values so a rolled-back node still reads document identity. Also removes Property's now-dead legacy writer switch (`IndexConfig.NativeWriter`, `SwitchIndexWriter`, `shard.store`) — native was already the only reachable production path — and moves the Property dump tool and the schema-property reader's document walk off `pkg/index/inverted` onto the native read-only API. The Stream element index (`idx/`) now also writes `_id` doc values, fixing a previous-release rollback reading its document IDs as zero. Every remaining confirmed-dead legacy scaffolding in `pkg/index/inverted` (the abandoned native-segment-plugin bridge, the superseded repair-page reader, and the read-only duplicates `pkg/index/native` already owns) is deleted outright rather than left unreferenced. Fixes a cold-first-lookup latency regression the native series index had carried since its own cutover (the per-segment identifier filter was built lazily, on first query, instead of once at segment-construction time); every `§13` performance target (write throughput, exact/prefix/wildcard lookup, index-order search, external receive) is now met, several by a wide margin. See the [NIDX-03 series index cutover verification](docs/design/archive/0.12.0/native-inverted-index/verification/nidx-03-series-cutover/README.md) report (rollback proof re-run against v0.11.1, the actual last published release, with a real crash-cut and a real gRPC round trip through a built-from-source previous-release binary); `banyand/stream/migration_element_index.go` (the Stream element-index migration tool, NIDX-04) remains the only production user of `pkg/index/inverted`, which is otherwise unused.
- (NIDX-04) Cut the Stream element-index migration tool over to the native index engine: `banyand/stream/migration_element_index.go`'s target-store writer and `banyand/stream/migration_verify.go`'s doc-count reader (renamed `CountElementIndexDocs`) no longer use `pkg/index/inverted`, so `banyand/stream`'s production (non-test) source no longer imports `pkg/index/inverted` or the retired third-party search engine at all (enforced by an updated dependency-guard test). The migration writer opens one native store per target shard behind its own throwaway root lease (matching the series-index union builder's and Measure's index-mode copy tool's established pattern), writes synchronously so a batch is durable before the call returns, and durably persists on close. The native reader opens both a native-rebuilt and a byte-copied previous-release (legacy-format) `idx/` directory transparently, so the migration's existing byte-copy fast path is unaffected.
- (NIDX-05) Remove the retired third-party inverted-index library from the repository entirely. `pkg/index/inverted` and `pkg/index/analyzer` are deleted; their remaining native-engine test coverage (checked-in historical fixtures and native-only read-path tests) moved to `pkg/index/native`, and the fixture corpora moved to `pkg/index/testdata` / `pkg/index/native/testdata`. The two series/element tag-filter range operators (`banyand/internal/sidx`, `banyand/stream`) now use `pkg/encoding`'s own sortable float/int64 encoding instead of the library's `numeric` package — byte-identical output, pinned by literal test vectors. `go.mod`/`go.sum` no longer reference the library, its ICE segment codec dependency, or any indirect dependency only they pulled in; `dist/LICENSE` and `dist/licenses/` are regenerated to match. The obsolete index-local lock filename is also removed, along with every constant, filter, fixture, and test that named or depended on it — writer exclusion was already owned by BanyanDB's own database lock, so this changes no observable behavior; a stray leftover lock file in an upgraded data directory is harmless and ignored by the native engine's directory scans. Compatibility evidence for v0.11.1-written directories survives only as checked-in, immutable fixture bytes with neutral provenance (a producing revision or a content hash); no test, tool, build script, or generated artifact depends on the retired library any more.
- Bound the native index's memory: merges stream to disk instead of materializing the merged segment, so their memory no longer grows with segment size or fan-in; persisted segments are no longer held in the heap but served from their files through `pkg/fs` (one descriptor per segment, term dictionaries read in place, a per-field bloom filter of at most 2 MiB kept for existence checks); and staged merge outputs and external segments are published by rename, so no staged name survives a restart. The on-disk format is unchanged and v0.11.1 directories open as before. In the 2.4M-series write-growth benchmark, peak RSS falls from about 1.7 GiB to about 450 MiB and the live heap after reopen from about 120 MiB to 6 MiB.
- Store BanyanDB's own logs in BanyanDB, behind `--logging-native-enabled` (off by default). Events land in the `_monitoring_log` stream group and are queryable through the ordinary stream API. Normal logging stays enabled and is never degraded by it; the two destinations have independent levels, so native can retain `info` and `warn` while stderr stays at `error`. Standalone and data nodes only in this change: like native metrics, each node writes its own logs through its local write path to shard 0 of the single-shard group. Six flags configure it (`--logging-native-enabled`, `-level`, `-modules`, `-levels`, `-exclude-modules`, `-ttl-days`); buffering, writing and memory are internal, and the sink drops and counts while the memory protector reports high pressure. The native log service's own logging and the storage of `_monitoring_log` are never collected, whatever `--logging-native-exclude-modules` says, and an event logged without a level is stored as `none`. Existing `GetLogger` callers need no change.
- Add logging related flags to the FODC proxy and agent. Every BanyanDB binary now shares the same logging flags and the matching `BYDB_LOGGING_*` environment variables.
- [Breaking Change] Remove the row-based query execution path from the Stream, Measure and Trace query engines. Measure TopN pre-aggregation is unchanged and still executes row-based. The `--stream-vectorized-enabled`, `--trace-vectorized-enabled` and `--measure-vectorized-enabled` flags are removed; a node started with one of them fails at startup with an unknown-flag error. A query shape the vectorized engine cannot plan now returns an error instead of falling through to row execution. See [Upgrading to 0.12](docs/operation/upgrade.md#upgrading-to-012).
- Push the criteria tag filter ahead of the vectorized stream merge, so a filtered index-order query bounds its merge at limit+offset. For such a query, where several rows share an ElementID, the criteria is now evaluated first and the element is represented by its first matching row in the requested sort order. Filtered timestamp-order queries are unchanged.
- Keep Stream filtering and client projection on the columnar batches until output, so a filtered distributed Stream query emits a native columnar frame instead of per-element protobuf. A filtered index-order query no longer re-evaluates the criteria per element: the pre-merge columnar filter already decided it, and only the hidden-tag removal remains. A filtered timestamp-order query evaluates the criteria on the batches at the position its element filter held, after the merge cap, so its documented under-fill is unchanged. The egress now drops criteria-only tags as whole columns, before it builds either response. So the protobuf response no longer builds an Element only to filter it away. The internal order key is not a tag column, so it stays. Traced queries and standalone queries keep the protobuf response.
- `measure.v1.QueryRequest.Aggregation` can now target a tag (`tag_name` + `tag_family`) instead of a field: `SUM`/`MIN`/`MAX`/`MEAN` over an `INT` tag, and `COUNT` over any scalar tag, in both standalone and distributed queries. Wire-additive only — existing clients that only ever set `field_name` are unaffected. See the [tag aggregation and time bucketing design](docs/design/0.12.0/tag-aggregation/README.md).
- `measure.v1.QueryRequest.GroupBy.time_bucket` groups a measure query by tumbling time windows, alone or combined with a tag `GroupBy`, in both standalone and distributed queries. The bucket width comes from the request or falls back to the measure's own `interval`. The part-scan path streams bucket-by-bucket so live memory never exceeds one bucket's groups; index-mode measures (no ascending-timestamp guarantee) use a bounded non-streaming fallback instead. A mixed-version cluster where an older data node ignores `time_bucket` is rejected with a clear error rather than silently collapsing the series to one row.
- Fold each maximal `(series, bucket)` span of a measure `GroupBy`/`Aggregation` once instead of per row whenever every group key — and, for `COUNT`/`COUNT_DISTINCT`, the aggregation target — resolves from the series index (an entity tag, or a tag carrying an `IndexRule`) rather than the part's tag columns: `COUNT_DISTINCT` collapses to one set insert per span and `COUNT` to one bulk increment, while `SUM`/`MIN`/`MAX`/`MEAN` and any non-index-resolved target still fold per row but skip the now-redundant per-row key computation and group lookup (the tag-aggregation design's §7.7 "run-folding" stage). Pure performance — results, the wire format, and the API are unchanged.
- Improve Canopy text readability: raise the faint and dim text contrast, lift every font size to at least 12px, use heavier sub-navigation weights, stop forcing antialiased font smoothing, and load IBM Plex Mono 600 and Sans 700. The query builder rail is wider by default (400px) to fit the larger text.
- `databasev1.Node` now reports its supported file format versions and IANA time zone name.
- Resolve BydbQL measure, stream and trace schemas from the liaison's watch-fed schema cache instead of the schema registry, which queried every metadata node on each request. A registry read is now made only when the cache has not yet seen a newly created resource. A BydbQL query no longer pays a metadata round trip per group (about 0.4–0.6 ms each on loopback), and no longer triggers the registry's read-repair of lagging metadata nodes.
- Decode null-free int64 and float64 measure columns straight into typed slices on the vectorized query path, instead of one heap-allocated byte slice per value that the batch then converted back. Filling an 8,192-row numeric column drops from about 0.5 ms and 8,196 allocations to 40–86 µs and 2 allocations. Merge, flush, TopN and columns containing nulls keep the byte form.
- Reference-count measure block cursors so batch string, bytes and string-array tag cells borrow the decoded block memory instead of copying each value; a cursor returns to its pool only when the last batch borrowing from it is released. Operators that keep values past their input batch (group-by, aggregation, TopN) and the response edge copy what they retain. Decoding an 8,192-row string column drops from 8,193 allocations to 1, and 33–58% in time. `BYDB_POISON_RELEASED_CURSOR=1` overwrites released cursor memory to expose use-after-release in tests.
- Emit every projected measure tag and field with a known schema type as a native typed column instead of a protobuf passthrough column, and build each response value in one allocation. Plain scans now decode without per-value wrappers and pay them only for rows that reach the response: on real stored blocks a full scan is 16% faster with 38% fewer allocations, limited and TopN scans 23–65% faster, and a distributed full-scan frame 49% faster with 99.7% fewer allocations. The wire format is unchanged.
- Stop allocating per input row in measure aggregation and TopN: group and replica-dedup keys are looked up from a reused buffer and copied only when a new group is inserted, and a TopN row that displaces the heap root reuses the root's storage. On real stored blocks, group-by + aggregation queries drop from about 103k to 2.8k allocations and TopN from 472k to 32k (15% faster).
- Stream vectorized measure scans one series window at a time instead of decoding every matching block before the first row. A series whose blocks do not overlap in time is handed to the pipeline block by block without copying, numeric and timestamp columns included, at block size (up to 8,192 rows); descending order uses a reversed selection instead of a reversed copy, and windows under 256 rows are coalesced. Overlapping segments still merge. On real stored blocks the eight gate workloads are 53% faster (geomean). New counters report how many windows and segments take the fast and the overlap path.
- Replace the eager decode-and-merge of time-ordered vectorized measure scans (the default when a query has no ORDER BY) with a time-ordered merge: a block is decoded only when the merge reaches its first timestamp and released as soon as its rows are consumed, keys are merged before values, and each column is gathered once per page with strings borrowed zero-copy. Output order is unchanged; peak decoded blocks drop from every matching block to about one per series. Multi-series queries over a shared time range are 54–57% faster on real stored blocks.
- Decode vectorized measure scan blocks on a node-wide pool sized to GOMAXPROCS instead of one goroutine per block, prefetching ahead in consumption order with a depth that grows while memory reservations succeed. Each block reserves its decoded size before decoding and releases it when the last batch borrowing from it is released, so a scan's memory is accounted by what it holds rather than checked once against its whole result: prefetch waits under memory pressure, the protector is consulted only when a query is admitted, and a query fails with the existing `block scan quota exceeded` error only when the block it needs next would put it over its own quota.
- Store a series' entity tags once per batch as a constant column in single-series vectorized measure batches, and aggregate by runs: when every group key is constant over a run of rows (constant columns, entity tags of a known series, or a time bucket over time-ordered rows), the group is looked up once per run and the run is folded with typed loops in the same order as before. Group-by + aggregation over real stored blocks is 57–68% faster; results are bit-identical.
- [Breaking Change] Add measure frame version 4, a columnar data-node-to-liaison wire format that replaces the row-oriented measure frame (version 3): each column's validity, offsets and values are sent as contiguous 8-byte-padded buffers, and the liaison builds columns by slicing the received message instead of allocating per cell. Data nodes always send version 4 and a liaison accepts only version 4 for measure frames, rejecting any other version with an error; there is no version negotiation and no fallback. BanyanDB 0.12 does not support rolling or mixed-version upgrades, so upgrade the whole cluster at once (stop every node, start the new binary); see [Upgrading to 0.12](docs/operation/upgrade.md#upgrading-to-012). Decoding a 4-column 8,192-row batch drops from 16,416 allocations and 0.85 ms to 38 and 0.14 ms for 6% larger frames; a distributed full scan is 38% faster.
- Add the data export protocol (`transfer.v1.ExportService`) and `bydbctl data export` with dry-run and CSV export, showing the progress and time of every file, unit and node.
- Add the data export dry-run protocol (`transfer.v1.ExportService`) and `bydbctl data export --dry-run`.
- Merge the local multi-group Stream query as columnar batches. The per-group batches go through one `SortedMerge` → `Distinct` → `Limit` pipeline and Elements are built once from its output, instead of one Element list per group merged row by row. A schema-evolved group keeps its own tags, and an ElementID returned by several groups is now returned once (first group wins). `logical_stream.MergeGroupElements` is removed.
- Stream distributed trace query results from data nodes to the liaison in chunks over a server-streaming transport, so a data node no longer materialises its whole result into one message. There is no longer a per-node 32 MiB response limit, cancelling a query now reaches the data nodes instead of letting them scan until a fixed deadline, and the fixed 5 s per-node deadline becomes a 15 s idle deadline that every chunk and data-node heartbeat resets; the liaison states the idle timeout in the request and the data node heartbeats at a fifth of it. A data node that fails during a trace query now fails the query instead of sometimes returning partial results silently. The unary `Query` response is unchanged.
- Stream distributed stream query results from data nodes to the liaison in chunks over a server-streaming transport, so a data node no longer materialises its whole result into one message. There is no longer a per-node 32 MiB response limit, cancelling a query now reaches the data nodes instead of letting them scan until a fixed deadline, and the fixed 5 s per-node deadline becomes a 15 s idle deadline that every chunk and data-node heartbeat resets; the liaison states the idle timeout in the request and the data node heartbeats at a fifth of it. A data node that fails during a stream query now fails the query instead of sometimes returning partial results silently. The liaison asks for chunks of at most 4096 elements and 4 MiB. The unary `Query` response is unchanged.
- Acknowledge trace `Write` streams per sealed batch while the stream stays open. The liaison groups each stream's rows per data node and seals a batch at 8 MiB or 200 ms after its first row, then sends the existing `WriteResponse` for every message of a batch as soon as its data node has applied it, instead of only after the client half-closes; liaison memory no longer grows with the length of the stream. `WriteResponse` gains `status_code` (the typed form of `status`) and `retry_after_ms` (a request to pause sending), and `model.v1.Status` gains `STATUS_SERVER_BUSY`, reported by a data node under memory pressure. The window of sealed, unacknowledged batches per node adapts (4 to begin with, growing to 16 on clean acknowledgements, halving when a node refuses a batch, and not growing while the liaison is under memory pressure); when it is full the liaison stops reading from the client, which blocks it through HTTP/2 flow control. A batch a data node refuses with `STATUS_DISK_FULL` or `STATUS_SERVER_BUSY` before applying it is retried by the liaison with backoff while acknowledgements carry `retry_after_ms`; if that lasts past the stream's deadline (30 s when the client set none) its messages are answered with `STATUS_SERVER_BUSY` and the stream ends with `RESOURCE_EXHAUSTED`. A batch whose outcome is unknown is reported, never replayed by the liaison. Clients that send everything and read afterwards keep working: responses leave through a queue that never blocks the receive loop. The request message is unchanged.
- Acknowledge stream `Write` streams per sealed batch while the stream stays open, as trace `Write` streams are. The liaison groups each stream's rows per data node, seals a batch at 8 MiB or 200 ms after its first row, and sends the existing `WriteResponse` for every message of a batch (keyed by its `message_id`) as soon as its data node has applied it, instead of only after the client half-closes; liaison memory no longer grows with the length of the stream. `WriteResponse` gains `status_code` and `retry_after_ms`, a data node under memory pressure answers `STATUS_SERVER_BUSY`, and the liaison retries such a batch (and a `STATUS_DISK_FULL` one) with backoff, bounded by the in-flight window and by the stream's deadline (30 s when the client set none), ending the stream with `RESOURCE_EXHAUSTED` when the pressure outlasts it. The batching, window and pressure behaviour is shared with trace. Clients that send everything and read afterwards keep working. The request message is unchanged.
- Canopy local authentication: a validated `auth` config (`CANOPY_AUTH_CONFIG`, `CANOPY_AUTH_*` overrides, `CANOPY_USERS` kept as an alias) with argon2id passwords (pure WASM, standard PHC strings; bcrypt still verifies with a startup warning), no default admin, and Horizon role names mapped to `admin`/`readonly`. Sessions are now server-side with sliding expiry (`canopy_sid` cookie) instead of an encrypted cookie, so logout revokes and role or user changes apply without re-login; existing sessions are signed out once on upgrade. API tokens (`auth.tokensFile`, `Authorization: Bearer hzn_<id>_<secret>`) authenticate as a named user whose role is re-resolved from the live config.

### Bug Fixes

- Stop rejecting stream, trace and property queries whose limit + offset exceeds 1792 when no memory limit is configured. Admission estimated 4 KiB per requested row before reading data, so OAP's default LIMIT 10000 failed with RESOURCE_EXHAUSTED even on tiny datasets; memory is still bounded by the 100,000-row window ceiling, the preallocation caps and the charges for data actually read.
- Apply trace query limits after span-ID and other residual filters so older matching traces remain queryable.
- Keep native index compaction progressing when persistence replaces unchanged in-memory segments with file-backed readers.
- Upgrade the Go toolchain to 1.26.10 for the crypto/x509 security fix (GO-2026-6809).
- Return zero for empty scalar QL `COUNT(DISTINCT)` and apply its pagination after the complete count instead of pruning native shard partials.
- Preserve indexed-array measure values, empty-entity selector semantics and retained merge-tail buffers in shared batch execution.
- Fix the liaison's distributed measure row merge wrapping borrowed frame strings into protobuf tag and field values without copying them.
- Fix a data node panicking with "directory is exist" when a write landed in a segment that retention had just removed but whose directory was still held by a reader; creating a segment over a directory pending deletion now returns `ErrSegmentDeleting`.
- Fix the stream block scanner counting each scanned block against the scan quota once per later block in its batch (and carrying the total across batches), which made a scan report `block scan quota exceeded` and wait for far more memory than its blocks need; the quota and the reservation now use the bytes of the current batch only.
- Fix data races in measure queries, which wrote the block cache and shard ID into parts shared with concurrent queries; both are now carried alongside each part.
- Fix a data node with several measure groups exporting query metrics only for the most recently opened group: opening a group closed every other group's query metrics. Each group now keeps its own.
- Fix the vectorized measure batch merge emitting a duplicate row when a same-series, same-timestamp duplicate straddled its 4,096-row page boundary; the row path already returned the deduplicated result.
- Fix stream queries silently dropping the later blocks of a series: the block filter's verdict is per-block, but `findBlock` advanced a whole series on skip.
- Fix a stream query with a small `limit` failing with `query memory pool exhausted` once it scanned more than the per-query allowance (8 MiB without a cgroup limit): the vectorized scan decoded and charged a whole segment before returning a row, and the sorted merge charged every batch it consumed, and neither charge was ever returned. The scan now decodes one scanner batch of blocks on demand and the query budget gains `Refund`, so the scan refunds a block when its cursor is released and the merge refunds a batch once a prune drops its last retained row. A data node now also reports a query over its memory allowance as `STATUS_RESOURCE_EXHAUSTED`, so clients receive `RESOURCE_EXHAUSTED` instead of a generic internal error. See apache/skywalking#14165.
- Fix a data race in Measure TopN where a pooled TopN value reused for a query wrote its tag names into the streaming processor's entity tag name slice.
- Stop `pkg/index/native`'s compaction-persistence test from flaking on `Test Pkg`: it asserted that garbage collection succeeds the instant a read view closes, without accounting for a background persist still holding an older root.
- Stamp `RELEASE_VERSION` into official release binaries so `--version` reports the release instead of `-`.
- Pack the source release from `git archive` and reject archives that contain ELF/Mach-O binaries.
- Stop declaring unbundled MCP npm dependencies in binary-package root `LICENSE` files (MCP Eyes output stays under `mcp/`).
- Keep MCP and Canopy dependency license texts under `mcp/licenses/` and `canopy/licenses/` (checked in). Go binary packages that stage MCP also ship `mcp/LICENSE`, `mcp/licenses/`, and `mcp/package-lock.json` with `mcp/dist`.
- Ship Canopy as an independent release archive (`skywalking-banyandb-*-canopy.tgz`) with built SPA/BFF artifacts and Canopy Eyes licenses.
- Include the full Apache-2.0 text in Canopy's root `LICENSE` and drop the accidental Linux-only `@rollup/rollup-linux-x64-gnu` hard dependency so `npm ci --omit=dev` works on macOS ARM64.
- Reject group / stream / measure / trace (and related) resource names that are not a single path-safe identifier (`[a-zA-Z0-9_]([a-zA-Z0-9._-]*[a-zA-Z0-9])?`), so names cannot escape catalog storage roots.
- Bound protobuf `validate.rules` on schema and query identifiers (max length, allowlist pattern, repeated max_items, numeric ceilings) so untrusted inputs cannot escape storage roots or force unbounded allocations.
- Honor the configured logging level in native observability metrics instead of retaining the pre-initialization debug logger.
- Fix FODC proxy `/metrics` returning partial data or timing out when concurrent scrapes overlap.
- Bound Property, Stream, and Trace query allocations with shared memory admission and capacity hints so oversized limit/offset windows cannot force huge result buffers.
- Preserve list-all / max-limit queries (`limit=MaxUint32` or OAP `Integer.MAX_VALUE`) with incremental scan admission and result-count accounting, without over-charging Property source payloads against the liaison fallback pool.
- Move the trace-pipeline plugin dynamic-lifecycle coverage out of `test/integration/{standalone,distributed}/pipeline` into a new `test/e2e/tracepipeline` gate (`make test-trace-pipeline`, `.github/workflows/test-trace-pipeline-e2e.yml`). The deleted suites forked a `banyand-server` binary through `pkg/test/setup/external.go`, which contradicted the project's "integration tests run in a single Go process" principle and silently skipped in CI because the prepare job did not build the binary. The new gate always builds the .so + CGO server it needs and runs against a real standalone process, so the dynamic Register/Update/Remove/InvalidConfig lifecycle plus the schema-store replay after process restart are now exercised on every PR that touches the trace pipeline. The same coverage is still available at the unit-test level in `banyand/trace/pipeline_watch_test.go` and `banyand/trace/pipeline_chain_filter_test.go`.
- Register the memory protector on the liaison role so query admission uses the cgroup-backed pool instead of the 64MiB fallback.
- Bound Cluster and Rover e2e BanyanDB memory so cgroup limits enable the query budget under resource-constrained environments.
- Enforce trace query time ranges independently of the sort index, skipping row timestamp checks when the query fully covers a part.
- Keep system native `memory_state` (with `kind` labels) from being overwritten by the liaison load-shedding gauge so self-observability dashboard queries succeed.
- Retry property schema registry initialization indefinitely, logging an error every 10 attempts.
- Authorize frames on write streams that were opened before RBAC was hot-enabled, so enabling RBAC mid-stream cannot leave long-lived Measure/Stream/Trace writes unchecked.
- Reload auth config when the watched path is a symlink and its target file changes (ConfigMap-style layouts).
- Re-fetch file/DNS discovery nodes that are parked in the retry queue while discovery has not Start()-ed yet, so unbounded PreRun schema-registry retries can recover once peers become reachable without restarting liaison.
- Keep DNS discovery `ListNode` successful when some SRV addresses refuse connections but at least one node was discovered, so non-meta nodes no longer deadlock in PreRun on their own not-yet-listening gRPC address.
- Fix un-interruptible sleep on shutdown during snapshot sync retry and add jittered backoff for stream, measure, and trace.
- Report the real shard ID in `CollectDataInfo` shard info for stream, measure, and trace instead of the live table's slice index, so a node that owns only higher-numbered shards is no longer attributed to shard 0 in cross-node shard-load analysis.
- Reject a measure or stream whose tag name appears in more than one tag family, or twice within one family, when it is created or updated. The query layer resolves a bare tag name against a flat map keyed by name alone, so such a schema previously registered successfully and then resolved that name differently depending on which query path read it. Already-persisted schemas keep loading unchanged; only the registry's create and update paths enforce the rule.
- Fix a silently wrong result from the vectorized measure liaison's aggregation reduce when a single per-node partial exceeds 65,536 rows: past that boundary the consuming row index wrapped, folding early rows into a group a second time and never visiting the rest, with no error. It is reachable today on `Top`-bearing queries, whose per-node limit is unbounded. The reduce now consumes an oversized partial in bounded chunks, and `BatchSize` is capped at `MaxUint16` so it cannot reopen the same wrap from the output side. The liaison's raw `Top` and raw `GroupBy` passes are chunked the same way; their callers already page at `BatchSize`, so that part is hardening rather than a live fix.
- Reject a `--trace-vectorized-batch-size` above 65,536 at startup instead of accepting it. The trace query path indexes a batch's active rows through a `uint16` selection, so a batch size above that bound silently wrapped -- reading early rows a second time and never reading the rest. The stream path already enforced this bound; measure now does too. A node configured above the bound will fail to start rather than return wrong results, and must lower the flag.
- Fix FODC proxy OOM kills on `/metrics`: stream the Prometheus text to the response, stop copying label maps, share one agent collection between concurrent scrapes, and install the same panic diagnostics as the agent.
- Stop the scheduled backup/lifecycle/retention scheduler from logging a false `action timed out` error for an action that runs longer than 5 minutes but ultimately succeeds. Crossing the internal 5-minute soft deadline now logs a lower-severity "still running" message and keeps waiting for the action's real outcome instead of abandoning it mid-flight; the eventual result is logged and the scheduler only starts the next scheduled run once the current one truly finishes.
- Fix backup reporting success when an earlier catalog upload fails.
- Return a trace's complete span set when its spans straddle a storage segment boundary (segments are per-day in local time, and each span lands in the segment matching its own timestamp) and the query's time range covers only one side of that boundary. After resolving the qualifying trace IDs from the segments the query range overlaps, fetching those traces' spans now also reopens any segment within one hour of the query range (`traceCompletionWindow`), so the neighboring day's spans are no longer silently dropped. Applies to both ORDER BY and trace-ID trace queries; trace selection, ordering, and limit/offset are unaffected.
- Fix multi-group Measure aggregations failing with `partial N schema mismatch` when the groups' schemas differ. A projected non-key tag that a group doesn't define is now null-filled before the liaison reduces the partials.
- Charge large tag and field values by their size instead of eight times it, so queries that read multi-MB values (for example SkyWalking OAP ai-agent session files stored as a `body` tag) no longer exhaust their memory allowance with `query memory pool exhausted`.
- Without `--allowed-bytes` or a container memory limit, size the query memory pool from the host's memory (75% of it, divided by 4, each query getting an eighth) instead of a fixed 64 MiB. The memory protector itself stays disabled: write backpressure, merge budgets and the protector's state are unchanged.
