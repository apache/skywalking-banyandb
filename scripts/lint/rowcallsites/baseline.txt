# row-result call-site baseline: the `Pull()` sites still standing after the
# row-based query execution path was removed in 0.12.0 (apache/skywalking#13998).
#
# `Pull()` returns a whole row result. Everything on the supported query path
# goes through the batch API instead. These sites remain because something
# still pins each one; the note on each entry says what.
#
# Format: one entry per line, `module-relative/path.go <count>`, forward
# slashes. Blank lines and lines starting with `#` are ignored. Counts are
# per file rather than line numbers so unrelated edits do not fail the build.
#
# Re-derive with: grep -rn --include='*.go' '\.Pull()' . | grep -v _test.go
#
# This is a textual ratchet, not an analyzer: a call split across lines or taken
# as a method value slips past it. Closing that needs a real go/analysis linter,
# as pkg/panicdiag/lintrawgo does. There is deliberately no per-site escape
# directive — the only supported change is removal.
#
# Policy: this list only ever SHRINKS. Removing an entry, or lowering a count,
# is the expected mode of change. Raising a count or adding a file fails
# `make lint` — write against the batch API instead. If you genuinely need a
# new one, that is a design discussion, not a baseline edit.
