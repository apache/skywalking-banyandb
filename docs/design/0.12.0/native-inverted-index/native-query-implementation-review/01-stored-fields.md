# Q1: native exact StoredFields lookup

Classification: **implemented and locally verified** (complete immutable resolver transition; two private read seams; not a tracking parent)

## Summary
Implement the complete immutable resolver transition over the committed-generation read-only seam (`ReadOnlyGeneration` backed by nativeice `Reader` dictionary and document visitation). Change `banyand/internal/dump/index_resolver.go:NewIndexResolver` so the real immutable `IndexResolver.Resolve` path and `IndexResolver.PartSeriesMap` path both use that native read owner in the same merge. Exact lookup and bounded identifier visitation are two private seams required by one resolver activation, not a general public iterator. This is an explicit scope change from the current live `SeriesStore` route: do not wrap it in `NewNativeStore` or any retired-engine runtime. Keep `Resolve` signatures and cache policy unchanged; do not hide a writer, publisher, recovery, merge, GC, or broad caller API migration in this ticket. Raw stored fields remain `map[string][][]byte`; the product adapter (`parseIndexedFields`) continues decoding rule IDs and tag values outside the codec without importing parent index/schema types into nativeice. It does not introduce a general query API or rely on a retired-engine runtime.

## Boundary

Proposed native seams (method names subject to the source audit): a bounded exact stored-field lookup on `ReadOnlyGeneration` for `Resolve`, and a bounded identifier visitor on the same committed view for `PartSeriesMap`, both exercised through real dump callers. The private codec visitor may be generic over terms, while the owned native surface is a narrow `VisitIdentifiers`-style method; it must not become a hypothetical generic query API. The caller opens one committed nativeice generation and owns its close; the adapter uses only that immutable view with explicit borrow/close lifetime. `SeriesStore.StoredFields`/`NewNativeStore` are not the native seams for this ticket; Q2’s later general SeriesIterator remains separate. No legacy `Query`, `Search`, match iterator, or collector may be constructed/delegated. No Boolean, range, MATCH, sort, aggregation, or scoring.

## Requirements

- Exact encoded document identity; absent identity returns nil without error.
- Return the first live matching physical document in snapshot order (one document-iterator advance); do not concatenate later duplicate logical IDs. Preserve every repeated value within that document and projection filtering; internal bookkeeping fields never escape.
- Apply the committed generation visibility rules and do not reopen a newer manifest during lookup. Preserve the existing open contract that skips an invalid newest generation in favor of the newest structurally complete older generation, and expose its selected `SnapshotID`. NRT publication ownership is outside Q1.
- Propagate context through both native seams and release cursor/scratch exactly once; bound projection/value bytes, identifier visitation, and result maps; return typed corruption/resource errors. The existing resolver uses `Background` and `PartReader.Iterator` also lacks context; preserve that wrapper limitation rather than silently migrating multiple APIs.

## Acceptance criteria

- **RED evidence:** No genuine RED cycle was captured before implementation; the initial discovery guard only proved that the agreed test names were absent and is not claimed as behavior RED. The implemented tests now provide the GREEN evidence:
  ```sh
  go test ./banyand/internal/dump/... ./pkg/index/native ./pkg/index/internal/nativeice ./pkg/index/inverted -count=1
  ```
  The pre-implementation discovery guard was:
  ```sh
  set -o pipefail
  go test ./banyand/internal/dump ./pkg/index/native ./pkg/index/internal/nativeice -list '^TestNative(StoredFields|PartSeriesMap)' | grep -Eq '^TestNative(StoredFields|PartSeriesMap)'
  ```
  It exited 1 with both packages compiling and no matching test names; that result is recorded as missing-test discovery, not RED behavior evidence.

- **Independent fixture:** hand-authored rows include duplicate logical IDs in known physical snapshot order, `series-a: [tag=one, tag=two]`, `series-b: [tag=red]`, with `series-b` deleted. Exact lookup returns the first live matching physical document only: the audited legacy primitive calls `dmi.Next` once, while the native replacement must stop its `VisitSelectedDocuments` callback after that first live match. Repeated values within that document remain `tag -> [[one],[two]]`; a later duplicate is not concatenated. Lookup of deleted `series-b` is nil; projection excludes internal `_id`/timestamp. For a multi-segment immutable dump fixture whose part metadata omits series values, `PartSeriesMap({sid-a,sid-b})` must return `{sid-a:entity-a,sid-b:entity-b}` and stop after both identifiers are found; it must not fall back to the old store or expose a public iterator. Per-segment identifier visitation need not provide global lexical ordering; it may stop when the requested result map is complete. Expected bytes/maps come from the retained oracle fixture's immutable content hash, not the implementation under test.
- **End-to-end:** construct the real native read owner through `NewIndexResolver`, call both `IndexResolver.Resolve` and the actual `PartSeriesMap` fallback against immutable dump fixtures, and verify values, deleted metadata identifiers, early-stop behavior, and reader lifetime. The production resolver imports only `pkg/index/native`; the native package's transitive dependency guard (`go list -deps .`) rejects `pkg/index`, `pkg/index/inverted`, and the retired index modules that `go.mod` redirects. This graph guard plus the real caller fixture replaces a synthetic execution counter/spy. Direct context tests separately prove cancellation on the committed read-only seam. NRT behavior remains blocked on NATIVE-OWNER; this leaf does not claim resolver cancellation or concurrent-publication/cache behavior is fixed.
- **Compatibility/lifecycle:** existing nativeice multi-segment segment/snapshot fixtures read successfully; selected complete generation and `SnapshotID` remain stable when the newest candidate is invalid; retained oracle fixtures provide compatibility evidence; no new writer is required; no file bytes, mtimes, or manifests change; malformed stored offsets return typed corruption within limits.
- **Cancellation/resource:** cancellation during stored-field visitation or identifier visitation returns `context.Canceled`, closes the owned cursor once, and does not retain projected buffers across calls. Identifier visitation is bounded and does not materialize all terms or posting counts.

- **Native-path guard:** the real `NewIndexResolver` integration test exercises both resolver operations against checked-in ICE bytes, while the native package transitive dependency test and the existing inverted boundary tests prove no retired Reader/Writer/Search/collector dependency is reachable on the native path. No synthetic production counter or spy is introduced.
- **Paired microbenchmark:** fixture construction is outside the timed region. The initial lookup-only profile showed that `VisitSelectedDocuments` rebuilt the stored-segment reader on every call: `newStoredSegmentReader` and its field-name/chunk-offset `pread`s accounted for most samples. Caching only the FST did not fix that path and was slower in the first experiment. The bounded fix reuses the immutable per-segment stored reader, serializes its existing reusable decode buffers under the established non-concurrent operation contract, and then reuses the reader's cached immutable FST. Five samples of `go test ./pkg/index/native -run '^$' -bench '^BenchmarkNative(StoredFields|PartSeriesMap)$' -benchmem -benchtime=1s -count=5` then measured exact lookup at approximately **3.4µs/op, 1,408 B/op, 25 allocs/op** native versus **5.0µs/op, 3,456 B/op, 50 allocs/op** oracle (median). The paired bounded identifier walk measured approximately **18.6µs/op, 5,152 B/op, 162 allocs/op** native versus **50.9µs/op, 9,687 B/op, 307 allocs/op** oracle. These are microbenchmark samples only, not a fresh-process paired macro benchmark or a production performance gate.
## Scope and readiness

Caller/seam: existing `banyand/internal/dump/index_resolver.go:NewIndexResolver` native read-owner construction -> `IndexResolver.Resolve` and `PartSeriesMap`, reached by dump measure/part readers, using `ReadOnlyGeneration` exact lookup and bounded identifier-visitor seams. This is intentionally a scope change from the current live `index.SeriesStore` route; it does not use `NewNativeStore`. Keep resolver signatures/cache policy and `PartReader.Iterator` unchanged. Exclude Q2's general SeriesIterator, writer lifecycle, writer fail-closed policy, and migration destination. **Readiness:** implementation complete and locally verified; no external or NRT-owner blocker applies. A genuine pre-implementation RED cycle was not captured, so the missing-test discovery result is not claimed as RED evidence.

Dependencies: source audit of the reusable committed-generation codec and pure native package seam; no external/NRT-owner dependency. Writer, publisher, recovery, merge, and GC work remain outside Q1. Relevant design rows: NQ-T01, NQ-T03, NQ-T04, NQ-T05.

Decision: two bounded read seams (exact lookup and identifier visitation) activate one immutable resolver transition in the same merge; no dormant general reader foundation.
