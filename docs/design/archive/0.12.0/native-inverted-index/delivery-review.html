Five mergeable tickets

Every merge replaces named live Bluge callers; no dormant foundation phase is allowed.

Implementation tickets and rollback

Five bounded cutovers replace the live Bluge surface. Each ticket is one reviewable main-branch merge unit.

!

Merge law: a parser, writer, query IR, shadow executor, benchmark, or fuzz harness cannot land without a named production caller switching to it in the same merge. NIDX-01 is a valid production slice because it removes direct Bluge readers from named read-only, schema, repair, and verification operations; it is not permission to merge an unused general reader.

NIDX-01 Read-only access count · walk · repair · verify
→

NIDX-04 Stream element idx filters · postings · sort

NIDX-01

Replace bounded read-only index access

Live Bluge feature replacedinverted.ReadOnlyDocCount, schema-property reader.WalkShard/WalkDocs, the Property repair scan, migration verification counts, and the source-read sides of index-mode copy and series union open committed directories through the native reader.

Inside this ticket

  • Bounded read-only open of the latest complete ICE v3/snapshot v3 generation without an exclusive writer lock.
  • Live-document count, match-all, exact term and exact-term OR, deletion masks, stored-field visit, and typed scalar decoding.
  • Ascending tuple sort and strict search-after for Property repair: group, name, entity ID, and timestamp.
  • Streaming iteration, concurrent-writer inspection, file-immutability proof, typed corruption errors, and CRC32 ignore behavior.

Explicit boundary

  • No insert, update, delete, batch, callback, near-real-time refresh, segment write, publication, merge, expiry, or GC.
  • No numeric/date range, prefix, wildcard, MATCH, NOT, HAVING, IN, analyzer, scoring, or generic collector surface.
  • No external-segment introduction and no native destination writer for copy, union, rebuild, or migration.
  • No runtime dependency deletion and no unused general query abstraction.
Merge proof · Named production callers return fixture-pinned counts, schema revisions, repair tuple/SHA pages, and migration-source documents from historical directories. File hashes and mtimes remain unchanged, concurrent writable indexes can be inspected, deleted documents remain absent, malformed data fails within bounds, and CRC32 values are ignored.

Rollback: select the retained legacy reader in the named callers. No writer drain, replay, conversion, or file change is required because NIDX-01 emits no index bytes.

NIDX-02

Replace the Property shard index

Live Bluge feature replacedproperty/db.newShard selects the native store for existing and new Property shards; its query and repair paths build on the bounded reader merged by NIDX-01.

Inside this ticket

  • Compatible ICE segment and snapshot publication for Property writes.
  • Property upsert/replacement, delete masks, stored fields, exact/boolean/range filter, and explicit sort.
  • Durable callbacks, snapshots, recovery, merge-time expiry, reference-safe GC, repair integration, and file snapshot.
  • Only analyzers, term codecs, query nodes, and write-format sections exercised by Property.

Explicit boundary

  • No series wildcard/dictionary surface.
  • No Stream element postings or MATCH analyzer family.
  • No external-segment receiver.
  • No general union, copy, verify, dump, or migration writer.
Merge proof · Update, query, ordered scan, delete/expiry, callback, repair, merge, restart, and backup all execute natively against a legacy-created shard. The pinned legacy binary then opens, queries, mutates, merges, and restarts it.

Rollback: drain the Property writer and select the retained legacy Property constructor on the same files. Startup fails instead of rewriting if the named rollback binary cannot accept the directory.

NIDX-03

Replace the per-segment series index

Live Bluge feature replacedinternal/storage.newSeriesIndex selects native sidx for Measure, Stream, and Trace, including their active replication path.

Inside this ticket

  • Field-set-aware insert-if-absent, update, version/timestamp, delete, and projection.
  • Exact/prefix/wildcard identity, field dictionaries, composed filters, stored lookup, and series/index/time sort.
  • Index-mode Measure reads and writes, stats, file snapshot, and cache reset.
  • Crash-safe external segment receive, validation, deduplication, introduction, and mixed-version replication.

Explicit boundary

  • No Stream element idx batch or paired posting API.
  • No element MATCH analyzer override.
  • No general union, copy, verify, dump, or rebuild writer.
  • No removal of the legacy adapter.
Merge proof · Real Measure, Stream, and Trace segment flows use native series insert, lookup, sort, replication, restart, snapshot, and raw segment receive. A rolling mixed-version replication test passes in both directions.

Rollback: stop native admission, drain external receive, and reopen the last committed generation with the retained legacy series constructor; no document replay or format conversion is allowed.

NIDX-04

Replace the Stream element index

Live Bluge feature replacedstream.newElementIndex selects the native idx writer, filter executor, posting collector, sorter, snapshot path, and external receiver.

Inside this ticket

  • Element batch write and near-real-time visibility with document-ID and timestamp postings.
  • Exact, existence, numeric/date range, AND/OR/NOT, HAVING, IN, prefix, wildcard, and MATCH filters.
  • Keyword, simple, standard, and URL analysis with MATCH AND/OR override.
  • Ascending/descending doc-value sort, snapshot/restart, and element-index raw segment receive.

Explicit boundary

  • No BM25, boosts, phrase, fuzzy, geo, highlighting, facet, or explanation surface.
  • No generic Bluge collector or plugin compatibility layer.
  • No remaining offline migration destination writers.
  • No dependency deletion before NIDX-05.
Merge proof · Production-shaped Stream writes immediately drive native EQ/NE/IN/HAVING, range, MATCH, NOT-universe, paired postings, sorting, restart, snapshot, and chunk-sync tests on legacy and native directories.

Rollback: the role-scoped switch returns only idx/ to the retained legacy constructor and reopens the same compatible snapshot after the writer is drained.

NIDX-05

Replace remaining admin/migration writers and remove Bluge

Live Bluge feature replacedUnion/rebuild, index-mode copy, migration output, dump, and every remaining maintenance/CLI caller use native administration APIs; runtime and offline Bluge dependencies are deleted.

Inside this ticket

  • Native verify, staged rebuild, union/dedup, index-mode reconstruction, and migration destination writing.
  • Complete document walk, stored/doc-value visitation, and sorted search-after extensions not already required by NIDX-01.
  • Rewire every remaining production and CLI caller; remove legacy query bridges, segment API types, modules, and replacements.
  • Retain a pinned legacy oracle binary and fixture corpus only as isolated compatibility test inputs.

Explicit boundary

  • No new disk version or opening-time migration.
  • No format rewrite merely to remove dependencies.
  • No unsupported search-product features.
  • No runtime legacy fallback after the approved retirement gate.
Merge proof · All named maintenance flows run against historical and native directories, source/dependency scans find no Bluge, ICE, or segment-API runtime edge, and the full two-binary compatibility matrix passes.

Rollback: redeploy the preceding native release on the unchanged ICE/snapshot files. Dependency removal may merge only after the declared legacy-retirement window; a Bluge runtime switch is no longer promised afterward.

NIDX-01 read-only operation contract

NIDX-01 is an operation slice, not a general reader layer. Its public surface is limited to the following production needs; migration copy and union continue to publish through their retained legacy writers until their destination paths are replaced by later tickets.

Operation Named callers Native behavior Result and bound
Open committed generation All NIDX-01 callers Inspect snapshot generations newest-first and pin the newest structurally complete ICE v3/snapshot v3 view without acquiring bluge.pid. Immutable snapshot handle; bounded record and section validation; no directory entry, byte, or mtime change.
Visible-document count inverted.ReadOnlyDocCount and migration verification Combine segment document counts with the pinned snapshot's deletion masks. One count in O(number of segments + deletion masks), without visiting stored documents.
Match-all document walk Schema walk, index-mode copy, and series union source reads Stream live local document numbers and visit every repeated stored field as raw name/value bytes. Caller-owned document callback; one document plus configured decode buffers in memory.
Exact term and exact-term OR Kind-filtered schema WalkShard Resolve exact FST terms, union the selected postings, remove snapshot deletions, and visit stored source/tombstone fields. Streaming matches; OR fan-out is bounded by the caller-supplied term count.
Stored and typed value access Schema decode, copy, union, and Property repair Preserve repeated raw values and expose only the scalar decoders required by the named adapters; internal-field policy stays in those adapters. Borrowed values are valid only during the visit callback; callers copy values they retain.
Ascending tuple page Property repair Order by (group, name, entityID, timestamp), return the stored SHA value, and resume strictly after all four prior sort components on the same pinned generation. At most the configured repair page size plus bounded sort state; no unbounded offset scan.

Ticket dependency and activation contract

Ticket Depends on Production activation in the merge Cannot be the ticket's only result
NIDX-01 Approved read fixtures and DEC gates Every named read-only caller uses native open/count/walk/search-after; no file is modified. A reader used only by tests, shadow comparison, or a future writer.
NIDX-02 NIDX-01 Native is the default Property constructor; legacy is an explicit rollback choice. A writer or query extension without the live Property write/lifecycle cutover.
NIDX-03 NIDX-02 Native is the default per-segment sidx constructor for all three TS products. Series executor without live write, snapshot, and replication paths.
NIDX-04 NIDX-03 Native is the default Stream element idx constructor. Shadow-only filter or test-only element writer.
NIDX-05 NIDX-01 through NIDX-04 plus retirement approval Every remaining admin/migration caller is native and runtime Bluge code is absent. A dependency cleanup that leaves a production or CLI Bluge bypass.

Shared merge gates

READ-001 MUST

NIDX-01 shall select and pin the newest structurally complete committed generation, apply its deletion masks, and leave file bytes, mtimes, and directory entries unchanged.

READ-002 MUST

NIDX-01 shall bound memory by configured page, block, section, term-count, and decode limits and return typed errors for malformed offsets, lengths, varints, and scalar encodings.

READ-003 MUST

NIDX-01 shall expose only committed-generation open, visible count, match-all, exact term, exact-term OR, stored-field visitation, required scalar decoding, and the Property repair tuple search-after.

READ-004 MUST

NIDX-01 shall remain safe beside an active legacy writer, shall not acquire the exclusive writer lock, and shall close all files and mapped regions when its pinned snapshot and iterators close.

ROLL-001 MUST

No native output may enter a rolling fleet before the named rollback binary can open, query, append, update, delete, merge, restart, recover, and receive raw external segments on the same directory.

ROLL-002 MUST

Capture every pre-merge differential mismatch as a reproducible artifact containing snapshot generation, canonical query, fixture-safe metadata, and both results. Shadow comparison is evidence, not a delivery ticket.

ROLL-003 MUST

Each ticket must switch every production operation named by its boundary to native in the same merge. Future-role code, disabled-only paths, and test-only implementations are prohibited from that ticket.

ROLL-004 MUST

No blocked ticket may merge before its predecessor merges and satisfies its production activation gate; an open pull request does not satisfy this dependency.

Operations, metrics, and performance

The native engine must make memory ownership, persistence lag, merge pressure, corruption, and rollback safety observable.

Signal Required dimensions Purpose
Batch admission product, result, document/byte/term counts Capacity and rejected-limit diagnosis.
Visibility/persistence latency generation, policy, p50/p95/p99 Separate query visibility from durability.
Snapshot state generation, segment count, live/deleted docs, refs MVCC and leaked-reader diagnosis.
Segment/cache memory mmap, FST, bitmap, stored, doc-value, evictable Bound resident and mapped memory.
Merge input/output bytes/docs, drops, duration, amplification Policy tuning and expiry health.
GC pending files/bytes, oldest age, removal failures Ref or filesystem blockage.
Integrity file kind, generation/segment, validation stage, error class Recovery and corpus evidence without leaking values.
Shadow comparison query class, mismatch class, backend, generation Rollout gate.

Benchmark dimensions

Record throughput; p50/p95/p99 latency; allocations; resident, mapped, and cache bytes; goroutines; disk size; segment count; write amplification; merge duration; startup/recovery time; and durable callback latency for product-shaped workloads. Budgets are approved from measured current workloads, not arbitrary parity percentages.

Maintainer decisions

These recorded choices are normative for the implementation. DEC-007 retains its explicit block disposition while the specification enforces the requested field-only CRC32 compatibility behavior.

Same-file rollback window

DEC-001

Recommendation: retain until one full release after native becomes default and the upgrade/downgrade matrix passes.

Historical release floor

DEC-002

Recommendation: select the oldest BanyanDB release represented by a collected, passing production fixture corpus.

Intentional defect fixes

DEC-003

Approve fixes for closing-write success, numeric exact terms, pure negatives, iterator ownership, and field-universe confusion.

Sort semantics

DEC-004

Recommendation: missing last in both directions, smallest encoded repeated value, identity/local-hit tie key, pinned search-after.

Epoch and negative timestamps

DEC-005

Recommendation: support full signed int64 nanoseconds and stop silently omitting values at or below zero.

Durable callback surface

DEC-006

Recommendation: support callbacks uniformly on element and series batches, with exactly-once terminal completion.

CRC32 compatibility field

DEC-007

Disposition: preserve the historical CRC32 fields only. Do not calculate, validate, cache, or use them for publication, recovery, or corruption classification.

Historical compressors

DEC-008

Recommendation: read only compressors proven by the historical corpus; emit verified S2 during the rollback window.

Resource limits

DEC-009

Recommendation: derive defaults from observed p99 workloads with explicit overrides and hard safety ceilings.

Identity sort support

DEC-010

Recommendation: specify and implement it only if a production planner contract is confirmed; otherwise reject it explicitly.

Read-only-first delivery slice

DEC-011

Disposition: split bounded native read-only operations from the Property writer/lifecycle cutover. The read-only ticket may merge only when every named production caller switches in the same merge and no unused general reader surface is exposed.
