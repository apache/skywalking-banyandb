Four mergeable tickets

Every merge cuts over one live Bluge path; no dormant foundation phase is allowed.

Implementation tickets and rollback

Four vertical cutovers replace the live Bluge surface. Each ticket is one reviewable main-branch merge unit.

!

Merge law: a parser, writer, query IR, shadow executor, benchmark, or fuzz harness cannot land as its own ticket. It must ship inside the first ticket whose named production constructor calls it and selects it by default for that index role.

NIDX-01 Property first complete native vertical
→
NIDX-02 Series sidx Measure · Stream · Trace
→
NIDX-03 Stream element idx filters · postings · sort
→
NIDX-04 Admin + removal last callers and dependencies
NIDX-01

Replace the Property shard index

Live Bluge feature replacedproperty/db.newShard selects the native store for existing and new Property shards; Property repair scans use the same native reader.

Inside this ticket

  • Bounded ICE v3 and snapshot readers plus compatible segment/snapshot publication.
  • Property upsert/replacement, delete masks, stored fields, exact/boolean/range filter, and explicit sort.
  • Durable callbacks, snapshots, recovery, merge-time expiry, reference-safe GC, repair scan, and file snapshot.
  • Only analyzers, term codecs, query nodes, and format sections exercised by Property.

Explicit boundary

  • No series wildcard/dictionary surface.
  • No Stream element postings or MATCH analyzer family.
  • No external-segment receiver.
  • No general migration or schema-reader API.
Merge proof · Update, query, ordered scan, delete/expiry, callback, repair, merge, restart, and backup all execute natively against a legacy-created shard. The pinned legacy binary then opens, queries, mutates, merges, and restarts it.

Rollback: drain the Property writer and select the retained legacy Property constructor on the same files. Startup fails instead of rewriting if the named rollback binary cannot accept the directory.

NIDX-02

Replace the per-segment series index

Live Bluge feature replacedinternal/storage.newSeriesIndex selects native sidx for Measure, Stream, and Trace, including their active replication path.

Inside this ticket

  • Field-set-aware insert-if-absent, update, version/timestamp, delete, and projection.
  • Exact/prefix/wildcard identity, field dictionaries, composed filters, stored lookup, and series/index/time sort.
  • Index-mode Measure reads and writes, stats, read-only count, file snapshot, and cache reset.
  • Crash-safe external segment receive, validation, deduplication, introduction, and mixed-version replication.

Explicit boundary

  • No Stream element idx batch or paired posting API.
  • No element MATCH analyzer override.
  • No general schema, union, copy, verify, dump, or rebuild command.
  • No removal of the legacy adapter.
Merge proof · Real Measure, Stream, and Trace segment flows use native series insert, lookup, sort, replication, restart, snapshot, and raw segment receive. A rolling mixed-version replication test passes in both directions.

Rollback: stop native admission, drain external receive, and reopen the last committed generation with the retained legacy series constructor; no document replay or format conversion is allowed.

NIDX-03

Replace the Stream element index

Live Bluge feature replacedstream.newElementIndex selects the native idx writer, filter executor, posting collector, sorter, snapshot path, and external receiver.

Inside this ticket

  • Element batch write and near-real-time visibility with document-ID and timestamp postings.
  • Exact, existence, numeric/date range, AND/OR/NOT, HAVING, IN, prefix, wildcard, and MATCH filters.
  • Keyword, simple, standard, and URL analysis with MATCH AND/OR override.
  • Ascending/descending doc-value sort, snapshot/restart, and element-index raw segment receive.

Explicit boundary

  • No BM25, boosts, phrase, fuzzy, geo, highlighting, facet, or explanation surface.
  • No generic Bluge collector or plugin compatibility layer.
  • No remaining offline migration callers.
  • No dependency deletion before NIDX-04.
Merge proof · Production-shaped Stream writes immediately drive native EQ/NE/IN/HAVING, range, MATCH, NOT-universe, paired postings, sorting, restart, snapshot, and chunk-sync tests on legacy and native directories.

Rollback: the role-scoped switch returns only idx/ to the retained legacy constructor and reopens the same compatible snapshot after the writer is drained.

NIDX-04

Replace admin/migration and remove Bluge

Live Bluge feature replacedSchema loading, union/rebuild, index-mode copy, migration verification, dump, and read-only count call native administration APIs; runtime and offline Bluge dependencies are deleted.

Inside this ticket

  • Bounded read-only open/count, latest generation, document walk, stored/doc-value visitation, and sorted search-after.
  • Native verify, staged rebuild, union/dedup, index-mode reconstruction, and migration verification.
  • Rewire every remaining production and CLI caller; remove legacy query bridges, segment API types, modules, and replacements.
  • Retain a pinned legacy oracle binary and fixture corpus only as isolated compatibility test inputs.

Explicit boundary

  • No new disk version or opening-time migration.
  • No format rewrite merely to remove dependencies.
  • No unsupported search-product features.
  • No runtime legacy fallback after the approved retirement gate.
Merge proof · All named maintenance flows run against historical and native directories, source/dependency scans find no Bluge, ICE, or segment-API runtime edge, and the full two-binary compatibility matrix passes.

Rollback: redeploy the preceding native release on the unchanged ICE/snapshot files. Dependency removal may merge only after the declared legacy-retirement window; a Bluge runtime switch is no longer promised afterward.

Ticket dependency and activation contract

Ticket Depends on Production activation in the merge Cannot be the ticket's only result
NIDX-01 Approved format fixtures and DEC gates Native is the default Property constructor; legacy is an explicit rollback choice. Codec, IR, writer, or fuzz code used only by tests.
NIDX-02 NIDX-01 Native is the default per-segment sidx constructor for all three TS products. Series executor without live write, snapshot, and replication paths.
NIDX-03 NIDX-02 Native is the default Stream element idx constructor. Shadow-only filter or test-only element writer.
NIDX-04 NIDX-01 through NIDX-03 plus retirement approval Every admin/migration caller is native and runtime Bluge code is absent. A dependency cleanup that leaves a production Bluge bypass.

Shared merge gates

ROLL-001 MUST

No native output may enter a rolling fleet before the named rollback binary can open, query, append, update, delete, merge, restart, recover, and receive raw external segments on the same directory.

ROLL-002 MUST

Capture every pre-merge differential mismatch as a reproducible artifact containing snapshot generation, canonical query, fixture-safe metadata, and both results. Shadow comparison is evidence, not a delivery ticket.

ROLL-003 MUST

Each ticket must switch its named production role to native in the same merge. Future-role code, disabled-only paths, and test-only implementations are prohibited from that ticket.

Operations, metrics, and performance

The native engine must make memory ownership, persistence lag, merge pressure, corruption, and rollback safety observable.

Signal Required dimensions Purpose
Batch admission product, result, document/byte/term counts Capacity and rejected-limit diagnosis.
Visibility/persistence latency generation, policy, p50/p95/p99 Separate query visibility from durability.
Snapshot state generation, segment count, live/deleted docs, refs MVCC and leaked-reader diagnosis.
Segment/cache memory mmap, FST, bitmap, stored, doc-value, evictable Bound resident and mapped memory.
Merge input/output bytes/docs, drops, duration, amplification Policy tuning and expiry health.
GC pending files/bytes, oldest age, removal failures Ref or filesystem blockage.
Integrity file kind, generation/segment, validation stage, error class Recovery and corpus evidence without leaking values.
Shadow comparison query class, mismatch class, backend, generation Rollout gate.
External receive bytes, retries, validation, dedup, introduction latency Migration reliability.

Benchmark dimensions

Record throughput; p50/p95/p99 latency; allocations; resident, mapped, and cache bytes; goroutines; disk size; segment count; write amplification; merge duration; startup/recovery time; and durable callback latency for product-shaped workloads. Budgets are approved from measured current workloads, not arbitrary parity percentages.

Open maintainer decisions

These choices must be explicit; the implementation must not decide them accidentally.

Same-file rollback window

DEC-001

Recommendation: retain until one full release after native becomes default and the upgrade/downgrade matrix passes.

Historical release floor

DEC-002

Recommendation: select the oldest BanyanDB release represented by a collected, passing production fixture corpus.

Intentional defect fixes

DEC-003

Approve fixes for closing-write success, numeric exact terms, pure negatives, iterator ownership, and field-universe confusion.

Sort semantics

DEC-004

Recommendation: missing last in both directions, smallest encoded repeated value, identity/local-hit tie key, pinned search-after.

Epoch and negative timestamps

DEC-005

Recommendation: support full signed int64 nanoseconds and stop silently omitting values at or below zero.

Durable callback surface

DEC-006

Recommendation: support callbacks uniformly on element and series batches, with exactly-once terminal completion.

CRC32 compatibility field

DEC-007

Disposition: preserve the historical CRC32 fields only. Do not calculate, validate, cache, or use them for publication, recovery, or corruption classification.

Historical compressors

DEC-008

Recommendation: read only compressors proven by the historical corpus; emit verified S2 during the rollback window.

Resource limits

DEC-009

Recommendation: derive defaults from observed p99 workloads with explicit overrides and hard safety ceilings.

Identity sort support

DEC-010

Recommendation: specify and implement it only if a production planner contract is confirmed; otherwise reject it explicitly.
