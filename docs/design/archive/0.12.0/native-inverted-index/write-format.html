FIELD-001 MUST

Reserve _id as field ID zero in newly written ICE segments; sort all remaining field names by raw byte lexical order before assigning IDs.

FIELD-002 MUST

Preserve repeated stored values and repeated doc-value terms; no API may silently collapse them unless that API explicitly requests a scalar.

FIELD-003 MUST

Treat stored bytes and doc-value terms as different representations. A Store + Sortable field may intentionally occupy both sections.

IDENT-001 MUST

An update publishes a replacement document and adds the previous live identity hit to a snapshot deletion mask atomically.

IDENT-002 MUST

Series ensure/upsert suppresses a new document only when the existing live identity already contains every requested field; otherwise it replaces/evolves the document.

IDENT-003 MUST

A delete-only mutation adds deletion state without writing a tombstone document.

Analyzers and term codecs

Persisted term bytes are part of disk compatibility. Matching requires the writer and query path to produce identical bytes.

Codec/analyzer Required behavior Golden boundaries Status
Keyword Emit one term containing the complete input bytes. Empty, zero byte, 0xff, Unicode, long binary. fixture
Simple Match pinned Unicode letter segmentation and case normalization. Scripts, combining marks, punctuation. fixture
Standard Match pinned token boundaries and normalization. URLs, email-like text, mixed scripts. fixture
URL Match BanyanDB URL token semantics. Scheme, host, path, query, escaped bytes. fixture
Numeric Reproduce sortable float transform and prefix-coded shift terms. Min/max, negative, ±0, precision edges. fixture
Timestamp Reproduce date/numeric encoding with inclusive range control. Epoch, negative, nanoseconds, bounds. decision
TERM-001 MUST

The native analyzer output and numeric/timestamp encodings must be specified independently and verified byte-for-byte against pinned fixtures before writer enablement.

TERM-002 MUST

Exact, range, and sort paths must use one shared term codec. Query-specific decimal formatting may not bypass persisted numeric encoding.

TERM-003 MUST

MATCH must support analyzer override and AND/OR token combination without exposing legacy analyzer types.

TERM-004 SHOULD

Reject non-finite numeric values unless an existing product contract and fixture explicitly require them.

!

The current exact numeric MatchTerms path may format decimal text while writes use numeric terms. This is a suspected adapter defect, not an approved native contract.

Stable design

One batch becomes one immutable segment and one snapshot transition.

Write and visibility semantics

Admission, analysis, byte sealing, memory visibility, persistence, and durable acknowledgement are separate milestones.

Normalize

Validate identity, field flags, timestamps, and batch limits.

Analyze

Assign IDs; build terms, stored values, and doc values.

Seal

Write one immutable byte-backed ICE segment.

Publish memory

Atomically install segment and replacement masks.

Persist

Publish compatible segment and snapshot files in order.

Acknowledge

Complete durable callbacks exactly once.

Direct builder staging

batch documents
  ├─ field catalog: field name → zero-based field ID
  ├─ stored rows: doc → repeated original values
  ├─ inverted rows: field → sorted term → docs + optional detail
  └─ doc-value rows: field → doc → sorted analyzed terms

seal order
  stored area
  for each field { term payloads → FST → optional doc values }
  global doc-value ranges → field records → fields index → footer

Logical view to physical section crosswalk

Builder view ICE v3 bytes produced Navigation root
Stored rows Compressed stored chunks, boundary directory, and one chunk-relative document offset per document. storedIndexOffset in footer.
Inverted rows Per-term frequency/norm stream, location stream, posting record, and one field FST after its terms. Dictionary address in the field record.
Doc-value rows Optional 1024-document chunks immediately after that field's FST, plus the global start/end range pair. docValueOffset in footer.
Field catalog Field records followed by their fixed-width address index. fieldsIndexOffset in footer.
WRITE-001 MUST

Reject the entire batch before publication if validation, analysis, allocation bounds, or segment sealing fails.

WRITE-002 MUST

Publish all documents, replacements, and deletion masks in one atomic in-memory snapshot transition.

WRITE-003 MUST

Never mutate a sealed segment or a deletion bitmap reachable by a published snapshot.

WRITE-004 MUST

Return a terminal error when the store cannot admit work because it is closing; silent success is prohibited.

WRITE-005 SHOULD

Bound staging memory by batch document count, total source bytes, fields, unique terms, postings cardinality, and analyzed expansion.

ICE v3 segment format

Readers bootstrap from a fixed 60-byte footer at EOF. There is no leading magic. All offsets are absolute from byte zero unless a subsection says otherwise.

Δ

This section is normative for the prototype but remains fixture-gated. A production writer may not ship until independently annotated files and bidirectional cross-read tests confirm every grammar rule.

Primitive encoding rules

uint32 / uint64 fixed width Big-endian.
uvarint 1…10 bytes Unsigned LEB128 as produced by Go binary.PutUvarint; malformed and overflowing values are errors.
offset uint64/uvarint Absolute file address unless explicitly described as a delta, length, chunk-relative offset, or end offset.
term order raw bytes Strict ascending lexical byte order within a field FST.
compression implicit No algorithm identifier exists in the file. Current pinned output uses S2; historical support is corpus-dependent.
version uint32 = 3 The pinned loader rejects every other segment version.

Reader bootstrap

  1. Require file length at least 60 bytes.
  2. Parse the footer backwards from EOF and require version 3.
  3. Validate root ordering, address arithmetic, field-index divisibility, counts, and configured allocation limits.
  4. Skip the reserved CRC32 field; validate structural bounds and codec framing independently.
  5. Load field records, stored chunk navigation, and doc-value readers without decompressing content.
  6. Load FST, postings, or compressed chunks lazily and pin their lifetime to the segment reference.
!

The existing loader parses the footer CRC but does not enforce it. The native reader intentionally retains the field for layout compatibility while neither calculating nor validating it.

Stored-field area

for each group of at most 128 documents:
    compressedChunk = Compress(concat(documentRecord...))

documentRecord :=
    uvarint(metadataLength)
    uvarint(dataLength)
    metadata[metadataLength]
    data[dataLength]

metadata := repeated {
    uvarint(fieldID)
    uvarint(valueStartWithinData)
    uvarint(valueLength)
}

data := concatenated original stored value bytes
storedChunkDirectory :=
    repeated uvarint(compressedChunkBoundary)
    uint32BE(encodedBoundaryByteLength)
    uint32BE(boundaryCount)

The boundary list begins with zero and supplies the start/end pair used for each compressed chunk. Compatibility fixtures must pin the boundary count emitted at empty and exact-128-document edges. At storedIndexOffset, one big-endian uint64 per document stores the document-record offset inside its uncompressed 128-document chunk.

Frequency/norm and location streams

chunkedIntegerStream :=
    uvarint(numberOfChunks)
    repeated uvarint(compressedChunkEndOffset)
    concatenated compressed chunks

freqNorm values per hit :=
    uvarint(encodedFrequencyAndHasLocations)
    uvarint(float32NormBits)

location values per hit :=
    uvarint(encodedLocationByteLength)
    repeated {
        uvarint(fieldID)
        uvarint(position)
        uvarint(start)
        uvarint(end)
    }

Posting-detail chunk size is derived from footer chunkMode. Modes at or below 1024 mean a fixed chunk size. Mode 1025 uses maxDocs / (cardinality / 1024 + 1). Division, zero, and overflow conditions must be bounds-checked.

Posting records and FST values

generalPostingRecord :=
    uvarint(freqNormAbsoluteOffset)
    uvarint(locationOffsetDeltaFromFreqNormOrAbsolute)
    uvarint(roaringByteLength)
    roaringPortableBytes[roaringByteLength]

FST value top-bit tags:
    00xxxxxxxx…  general: lower 62 bits are posting-record absolute offset
    01xxxxxxxx…  reserved; reject
    10xxxxxxxx…  one-hit: 31-bit positive norm + 31-bit local doc number
    11xxxxxxxx…  reserved; reject

The one-hit form is valid only when the term has one document, frequency one, no locations, a positive encodable norm, and a document number fitting 31 bits. The initial native writer may always use the general form if legacy cross-reading proves it valid.

Per-field FST and doc values

fieldDictionary :=
    uvarint(vellumByteLength)
    vellumBytes[vellumByteLength]

docValueTermStream := repeated encodedTerm
encodedTerm := escapedTermBytes 0xff
escape rules := prefix byte 0xff or byte 0x5c with 0x5c

docValueChunk :=
    uvarint(documentEntryCount)
    repeated {
        uvarint(docNumberDelta)
        uvarint(termEndOffsetDelta)
    }
    compressed concatenated term streams

fieldDocValues :=
    concatenated 1024-document chunks
    repeated uvarint(chunkEndOffset)
    uint64BE(encodedChunkOffsetByteLength)
    uint64BE(numberOfChunks)

After every field is written, the global doc-value index stores one uvarint start/end pair per field. Both values are MaxUint64 when that field has no doc values.

Field records and fields index

fieldRecord :=
    uvarint(dictionaryAbsoluteOffset)
    uvarint(fieldNameByteLength)
    fieldNameBytes
    uvarint(documentsContainingField)
    uvarint(totalAnalyzedTokens)

fieldsIndex := repeated uint64BE(fieldRecordAbsoluteOffset)

The fields index begins at fieldsIndexOffset and ends immediately before the footer. Its byte length divided by eight determines the number of field records.

The 60-byte footer

numDocs 8
storedIndex 8
fieldsIndex 8
docValues 8
chunkMode 4
timeMin 8
timeMax 8
version 4
CRC32 (reserved) 4

All footer fields are big-endian and appear in the displayed order. The terminal CRC32 field remains a four-byte reserved compatibility slot: native code preserves its position but does not calculate, validate, or use its value. Time bounds preserve signed int64 bit patterns through a uint64 cast.

ICE-001 MUST

Read and write segment type ice, version 3, using this grammar throughout the same-file rollback window.

ICE-002 MUST

Reject every count, length, offset, delta, decompressed size, FST value, or bitmap that exceeds its containing range or configured resource limit before allocation or slicing.

ICE-003 MUST

Pin exact Vellum and Roaring versions used for compatible output; dependency upgrades require cross-version fixtures.

ICE-004 MUST

Determine the compressor from directory provenance/configuration or verified historical policy; never guess by accepting unchecked decompression output.

Fixture gate

The manifest is the commit record and owns deletion state.

Snapshot v3 manifest format

A .seg file is immutable data. A .snp file selects the live segment generation and stores logical deletion bitmaps.

File naming

snapshot final name := lower-case hexadecimal numeric ID, conventionally width 12, + ".snp"
segment final name  := lower-case hexadecimal numeric ID, conventionally width 12, + ".seg"
writer lock         := "bluge.pid" during compatibility window

Readers accept hexadecimal IDs and order them numerically. Temporary/staging names must not match accepted final-name enumeration.

Snapshot v3 grammar

snapshotV3 :=
    uvarint(version = 3)
    uvarint(segmentCount)
    repeated segmentRecordV3[segmentCount]
    uint32BE(reservedCRC32)

segmentRecordV3 :=
    uvarint(typeByteLength)
    typeBytes                         // "ice"
    uint32BE(segmentVersion)          // 3
    uvarint(segmentID)
    uint64BE(segmentSize)
    uint64BE(segmentDocumentCount)
    uint64BE(segmentTimeMinBits)
    uint64BE(segmentTimeMaxBits)
    uvarint(deletionBitmapByteLength)
    roaringPortableDeletionBytes

The final CRC32 field remains at its historical four-byte position but is reserved for compatibility only; native code neither calculates nor validates it. The deletion bitmap contains segment-local document numbers. Length zero means no deletions.

Read compatibility

Snapshot version Metadata after segment ID Native reader policy Native writer
1 None before deletion bitmap. Accept only if historical fixtures require it. Never emit.
2 timeMin, timeMax as two uint64BE values. Accept only if historical fixtures require it. Never emit.
3 size, docCount, timeMin, timeMax as four uint64BE values. Required. Required during rollback window.
SNP-001 MUST

Publish only a snapshot whose referenced final segment files exist, validate successfully, and match their recorded type, version, size, count, and time bounds.

SNP-002 MUST

Treat snapshot deletion bitmaps as immutable after publication; writers clone before adding update or expiry drops.

SNP-003 MUST

Preserve but ignore the snapshot CRC32 field; select a generation using the remaining structural and referenced-segment validation.

SNP-004 MUST

If the newest snapshot is malformed or references an unusable segment, recovery may select the newest older fully valid generation; it must report degradation.
